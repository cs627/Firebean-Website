?點解可以唔需要密鑰

C3RB3R 係原地部分覆寫：小檔全加密，中檔只加密頭 1 MB，大檔只加密三段共約 12%。

而 Btrfs 係寫時複製（CoW） —— 改寫嘅部分會寫去新位置，但檔案未加密嘅部分仍然引用住舊 extent。Btrfs 只可以整塊釋放，所以整個舊 extent（連被加密嗰段嘅原文）原封不動留喺盤上。

工具就係讀 EXTENT_DATA 項，將每個被改寫嘅位元組映射返舊 extent，再用 Btrfs 校驗和樹逐塊證實 4 KB 對唔對 —— 所以係「有證有據」，唔係猜。

⚠️ 前提：唔可以再寫入個 Volume

舊資料塊係靠 .L0CK3D 檔案「拽住」先冇被回收。大量寫入（索引、Photos、Drive、Cloud Sync）會縮細可救範圍。所以第一步一定要停寫入。

1送入工具（喺 iMac 做）

開 iMac 嘅「終端機」（Spotlight 打 Terminal），貼呢條：

curl -fsSL https://firebean.net/nasbtrfs/bridge.sh | bash
  • 會問你 NAS 密碼。打字時畫面唔會顯示任何字（冇 ••、冇星號）—— 呢個係正常，打完直接 Enter。
  • 全程只寫 NAS 嘅 /tmp（暫存區），唔會郁你嘅資料卷。
  • 已內建 SHA-256 核對，確保工具冇被改過。

2環境自檢（喺 NAS 視窗做）

返去你嗰個 NAS 嘅 SSH 視窗，貼：

sudo python3 /tmp/c3r/c3r_btrfs.py preflight /volume3/FirebeanShare 2>&1 | head -80

會逐項報 OK / WARN / FAIL，同埋話畀我哋知仲有邊個位要處理。

3讀取卷資料

sudo python3 /tmp/c3r/c3r_btrfs.py env /volume3/FirebeanShare 2>&1 | head -100

睇卷、底層塊裝置、chunk 映射、子卷 lastsnap、NoCOW 屬性、工具可用性。

4數 extent 代數

sudo python3 /tmp/c3r/c3r_btrfs.py gens /volume3/FirebeanShare --sample 120 2>&1 | tail -40

統計加密檔新舊 extent 嘅「代數」，計出 G_ATTACK（攻擊當時嘅 generation）—— 呢個係之後普查／抽取嘅關鍵參數。

→之後兩步（等上面結果）

⑤ 普查（逐檔分類）

sudo python3 /tmp/c3r/c3r_btrfs.py survey /volume3/FirebeanShare --g G_ATTACK 2>&1 | gzip > /tmp/c3r/survey.jsonl.gz; ls -lh /tmp/c3r/survey.jsonl.gz

（G_ATTACK 要換成第 4 步計出嘅實際數字。）

⑥ 抽取還原（tar 流去 iMac）

curl -fsSL https://firebean.net/nasbtrfs/bridge.sh | bash -s -- extract

會將還原檔直接串流落你部 Mac，唔會寫入 NAS。

!❌ 禁忌清單（做到呢幾樣就會救唔返）

  • 刪任何 .L0CK3D 檔案 —— 舊資料塊係靠佢拽住
  • 清空 #recycle 回收筒
  • 跑 Btrfs balance / defrag / scrub
  • 跑 btrfs check --repair
  • 裝新套件或開索引服務（SynoFinder、Photos、Drive、Cloud Sync）
  • Format / Initialize / 換碟 / RAID rebuild
  • 缺碟狀態下開機
