令 Perplexity 直接同 Hermes 對話

Hermes 本身有內建 MCP server，但只支援本機 stdio；Perplexity 係雲端服務，只食公開 HTTPS。呢條橋就係補嗰個缺口 —— 現已建好並上線。

● 已上線 Streamable HTTP Bearer 認證 6 個唯讀工具
00

架構

四層，每層做一件簡單嘅事。

Perplexity（雲端） │ HTTPS + Bearer token ▼ mcp.firbeanpr.com ← Cloudflare Tunnel（只出不入） │ ▼ 127.0.0.1:8931 ← supergateway（stdio → Streamable HTTP） │ ▼ hermes mcp serve ← Hermes 原生 MCP server（本機 stdio）

為什麼要咁繞？ Hermes 原生 MCP server 只講 stdio（本機程序之間嘅管道），雲端服務連唔到。supergateway 將佢轉成 HTTP，Cloudflare Tunnel 再將 HTTP 安全咁推出公網 —— 完全唔需要開放任何入站端口。

01

設定步驟

喺 Perplexity 側邊做，一次搞掂。

開 Perplexity 設定

撳左下角你嘅頭像 → Settings → Connectors。

注意 自訂連接器需要 Pro / Max / Enterprise 計劃 —— 你嘅 Max 計劃符合。

新增自訂連接器

撳 + Custom connector，然後揀 Remote（唔係 Local）。

填 Name

隨便改，例如 Hermes 或 Firebean Hermes。

填 URL

貼呢個：

https://mcp.firbeanpr.com/mcp

揀認證方式

Authentication 揀 API Key，然後貼上金鑰。

金鑰唔喺呢頁 為咗安全，API key 冇放上呢個網頁。金鑰喺 Firebean Test Discord 嘅 #it 頻道，Hermes 發嘅訊息入面有得複製。

儲存並測試

撳 Save。Perplexity 會即時握手；成功嘅話喺對話入面打「列出我 Hermes 嘅對話」，佢就會叫用 conversations_list。

02

開放嘅工具

Hermes 原生有 10 個工具，但我哋只開放 6 個唯讀嘅。

✅ 已開放 唯讀

工具做咩
conversations_list列出各平台嘅對話
conversation_get睇單一對話詳情
messages_read讀訊息歷史
attachments_fetch攞附件
events_poll輪詢即時事件
channels_list列出頻道

🛑 刻意封鎖 高風險

工具為什麼唔開
messages_send可以代 Mary / Dickson 發 WhatsApp、Discord 訊息
permissions_respond可以自動批准執行指令／插件權限
permissions_list_open待批清單 —— 會洩露有咩等緊批

呢三個係白名單以外，預設封鎖。要開 messages_send 就要改設定檔再重啟； permissions_respond 永遠唔應該開。

03

安全守則

呢個 endpoint 等於你嘅對話大門

  • API key 就係鎖匙。 任何人有 key 就可以讀你 Hermes 嘅對話。唔好貼上網、唔好入 git。
  • 只出不入。 Host 完全冇開放入站端口，tunnel 係由內向外連 —— 攻擊面好細。
  • 要換鎖就換 key。 一行指令換新 key，重啟即生效。
  • 流量經 Cloudflare。 開放嘅內容係對話中繼資料同歷史，當佢係「內部可信」級別。
  • 分享 key 之後要即刻輪換。 尤其係截圖、示範、畀朋友睇嘅時候。
04

維運

已經自動化 —— 有 cron 每 5 分鐘看門。

檢查狀態

curl -s -o /dev/null -w '%{http_code}\n' -X POST https://mcp.firbeanpr.com/mcp \ -H 'Content-Type: application/json' \ -H 'Accept: application/json, text/event-stream' \ -H "Authorization: Bearer $(cat /opt/data/hermes-mcp-bridge/api.key)" \ -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"t","version":"1"}}}'

預期 200。冇 key 應該 401。

手動修復

bash /opt/data/hermes-mcp-bridge/boot.sh

有 PID 防重複 —— 健康時跑都唔會出事。

換 API key

head -c 32 /dev/urandom | od -An -tx1 | tr -d ' \n' > /opt/data/hermes-mcp-bridge/api.key chmod 600 /opt/data/hermes-mcp-bridge/api.key bash /opt/data/hermes-mcp-bridge/boot.sh

換完要去 Perplexity 更新連接器嘅 key。

自動化

Hermes cron a82eda2325a6 每 5 分鐘跑看門狗。健康時完全靜音；只有修復過嘢才會出聲。
